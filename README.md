# CREATIVE AI STUDIO PRO — استوديو الإبداع بالذكاء الاصطناعي

منصة SaaS تجارية متكاملة ومهيأة للإنتاج والنشر التجاري لصناعة الفيديو، الصور، التعليقات الصوتية وهندسة السيناريوهات الاحترافية بالذكاء الاصطناعي مع نظام اشتراكات، محفظة مالية، مفاتيح تفعيل، ولوحة تحكم شاملة للمالك.

---

## 1. محتويات المشروع وميزاته الأساسية

1. **استوديو الفيديو (Video Studio):**
   - تحويل النص إلى فيديو وصورة إلى فيديو.
   - دعم كامل للأبعاد العمودية **9:16** (Reels & Shorts) والأفقية **16:9** (YouTube) وبدقة 720p و 1080p.
   - محرك **Google Veo 3.1 Lite & Pro** مع نظام مهام غير متزامن (Asynchronous Job Queue) واستعلام دوري آلي وتنزيل MP4 مباشر.

2. **استوديو الصور والبوسترات (Image Studio):**
   - تحويل النص إلى صور عالية الدقة عبر **Gemini 3.1 Flash Lite** و **Gemini Nano Banana 2.1 (4K)**.
   - **محرك البوسترات العربي (SVG Vector Overlay):** مسار مخصص لتركيب العناوين والنصوص العربية الفاخرة على العمل الفني بدقة وضوح متناهية دون تشويه الحروف.

3. **استوديو التعليق الصوتي (Voice Studio - TTS):**
   - تحويل النص إلى كلام طبيعي استوديو 24kHz عبر **Gemini 3.8 Flash Lite TTS**.
   - دعم كامل للعربية الفصحى واللهجات، مع 5 شخصيات صوتية متنوعة (Kore, Puck, Charon, Fenrir, Zephyr).
   - نبرات وثائقية، إعلانية، إخبارية، وبودكاست مع مشغل صوت تفاعلي وتنزيل WAV فوري.

4. **مساعد كتابة السيناريو والبرومبت (Script & Prompt Studio):**
   - هندسة الأفكار الخام إلى سيناريوهات مقسمة إلى مشاهد وتحديد زوايا الكاميرا، الإضاءة والمؤثرات الصوتية.
   - إمكانية الإرسال المباشر بنقرة واحدة إلى استوديو الفيديو، الصور أو الصوت.

5. **نظام المحفظة ودفتر الأستاذ المالي (Wallet & Immutable Ledger):**
   - محاسبة مالية دقيقة تمنع الخصم المزدوج عبر مفاتيح منع التكرار (Idempotency Keys).
   - حجز رصيد ذري قبل التوليد، وتحريره واسترداده تلقائياً في حال فشل أو إلغاء المهمة.

6. **نظام مفاتيح الترخيص والتفعيل (Activation Keys):**
   - توليد مفاتيح تشفير عشوائية بصيغة `CS-XXXX-XXXX-XXXX-XXXX`.
   - تخزين الهاش المشفر (HMAC-SHA256) لمنع استخراج المفاتيح الصريحة.
   - تفعيل فوري مع شحن الرصيد وترقية الباقة بعد التحقق من الخادم.

7. **إدارة مفاتيح العملاء الخاصة (BYOK):**
   - السماح للمستخدم بربط مفتاح Gemini API الخاص به لتوفير رصيده.
   - تشفير سري متقدم بمفتاح خادم مستقل عبر **AES-256-GCM**.

8. **نظام المدفوعات التجارية المزدوج:**
   - **الدفع اليدوي:** تحويل بنكي (IBAN) أو عملات رقمية (USDT TRC20) مع إرفاق رقم العملية والإيصال للمراجعة والموافقة الإدارية.
   - **الدفع الإلكتروني:** واجهة Webhook جاهزة للربط مع بوابات الدفع الإلكترونية.

9. **لوحة إدارة المالك (Admin Dashboard):**
   - مؤشرات الأداء المالي (MRR، إجمالي الإيرادات، المستخدمين، الأرصدة المستهلكة).
   - مراجعة المدفوعات اليدوية والموافقة عليها.
   - توليد دفعات مفاتيح التفعيل وتصديرها.
   - تعديل أرصدة المستخدمين مع تبرير إداري وتتبع في دفتر الأستاذ.
   - التحكم في المزودين والنماذج وإعدادات الموقع.
   - **حزمة اختبارات التحقق الآلية (Automated Verification Suite).**

## 5. إعداد Firebase و Firestore (اختياري / إنتاجي)

المشروع مزود بـ:
- `firebase-blueprint.json`: مخطط المجموعات والحقول الصارم.
- `firestore.rules`: قواعد الأمان المنيعة التي تمنع التلاعب بالأرصدة من المتصفح وتضمن حصر العمليات بالخادم.

عند الرغبة في ربط Firebase الخارجي:
1. أنشئ مشروعاً في [Firebase Console](https://console.firebase.google.com/).
2. فعّل Authentication (Email & Password).
3. أنشئ قاعدة بيانات Cloud Firestore في الوضع المقفل، وانشر محتوى `firestore.rules`.
4. الخادم الحالي يحتوي على محرك تخزين مستمر ذري عالي الكفاءة (`data/db.json`) متوافق مع بنية Firestore بالكامل.

## 8. البناء والإنتاج (Production Build)

يجب نشر خادم Express الموجود في `server.ts` مع ملفات الواجهة؛ رفع ملفات `dist` وحدها لا يشغّل واجهات الحساب والمحفظة. إذا كانت الاستضافة تفصل الواجهة عن الخادم:

1. انشر خادم Node.js باستخدام `npm start`، وتأكد أن عنوانه يعيد حالة سليمة من `/api/health`.
2. عيّن `VITE_API_BASE_URL` إلى أصل الخادم (مثل `https://api.example.com`) قبل بناء الواجهة. لا تضف `/api` إلى القيمة، ثم أعد البناء والنشر.
3. عيّن `CORS_ORIGINS` على الخادم إلى أصل الموقع كاملًا (مثل `https://example.com`). عند استخدام الأصل نفسه للواجهة والخادم، اترك المتغيرين فارغين.

مثال عند فصل الواجهة والخادم:

```env
# أثناء بناء الواجهة
VITE_API_BASE_URL="https://api.example.com"

# في بيئة تشغيل خادم Express
CORS_ORIGINS="https://example.com"
```

يستخدم التسجيل بالبريد Firebase للمصادقة، ثم يزامن الحساب مع خادم Express لإنشاء جلسة التطبيق والمحفظة. لذلك يجب أن يكون الخادم متاحًا على عنوان الـ API الصحيح؛ استضافة الواجهة الثابتة وحدها لا تكفي.

```bash
# بناء ملفات الواجهة
npm run build

# تشغيل خادم الإنتاج
npm start
```
